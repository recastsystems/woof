# WRF 4.7.1 shallow convection

`shcu_physics=1` is the Registry's G3 shallow selector. WRF 4.7.1 has an
empty `G3SHCUSCHEME` case in `phys/module_shallowcu_driver.F:514`.
WOOF accepts the setting and performs the same empty stage. It must not
be confused with the deep Grell 3-D scheme.

`shcu_physics=3` selects GRIMS. It uses the current PBL depth and level,
YSU/Shin-Hong convective velocity and entrainment depth, and the current
deep-convection rain increment. Native WRF admits PBL 1, 5, 6 and 11;
WOOF refuses other pairings instead of silently resetting the selector.

`shcu_physics=4` selects NSCV (the NSAS shallow scheme). It returns heat,
water, condensate and momentum tendencies and shallow rain. `sas_pgcon`
also applies to this selector. Native WRF refuses its combination with
`cu_physics=96`, which already contains this shallow stage. Native WRF
also refuses any shallow selector with the MYNN EDMF switch enabled.
The importer and run configuration share these pairing checks.

The recovered October CUDA ports use REAL32 arithmetic. Both native
modules are byte-identical in WRF 4.6.1 and 4.7.1:

| Native module | SHA-256 |
|---|---|
| `module_shcu_grims.F` | `2b56ceb8d8c806179bb1e60b29174fd62ca8c4149fc487ecafa613ff937b131d` |
| `module_shcu_nscv.F` | `d244722bce55d85a519edd305d78d575ecc8bd1309780cd4ed9c1c4b323067c7` |

GRIMS tables are kept in `woof/data/grims/grims_tables.npz`; their hash is
checked by the launcher. The native modules ship under WRF's public-domain
statement. The source history is retained in the lane's prior-work bundle.

## Replay

The referee is native WRF 4.7.1 commit
`f52c197ed39d12e087d02c50f412d90d418f6186`, GNU Fortran, REAL32, dmpar,
`-O2 -fno-fast-math -ffp-contract=off -fno-tree-vectorize`. The capture
instrument adds stream writes around the native shallow call, without
changing scheme arithmetic. Run it on a private native source copy:

```sh
python tools/shallow_wrf471_capture.py NATIVE_COPY --base-input BASE_INPUT
cd NATIVE_COPY
./compile -j 4 em_real
```

The script creates sibling `native-shcu0`, `native-shcu1`, `native-shcu3`
and `native-shcu4` directories. In each run directory:

```sh
export WOOF_SHCU_CAPTURE="$PWD/capture"
mpirun --allow-run-as-root --oversubscribe -np 4 NATIVE_COPY/main/wrf.exe
```

The kept case is the 2000-01-24 12Z WRF real-input tutorial domain:
74 x 61 x 35 staggered points, 30 km, 60 s step, three hours, YSU, Noah,
RRTMG, no deep convection, MP6. The capture contains every column in
four tiles at steps 1, 31 and 61, including active shallow columns.
All exact comparisons use unsigned 32-bit words, including signed zero.

```sh
GPUWM_WRF_EXACT=1 python tools/shallow_wrf471_replay.py \
  native-shcu3/capture/*.bin --output replay3.json
GPUWM_WRF_EXACT=1 python tools/shallow_wrf471_replay.py \
  native-shcu1/capture/*.bin --output replay1.json
```

NSCV leaves some column cloud-base and cloud-top diagnostics unwritten.
The witness initializes only the native wrapper's local integer `kbot`
and `ktop` arrays to two distinct sentinels before calling the unchanged
native `nscv2d`. The replay excludes only individual output words changed
by these seeds. It asserts that every tendency, rain rate, and defined
diagnostic also matches the original whole-forecast capture:

```sh
python tools/shallow_wrf471_nscv_witness.py \
  NATIVE_COPY/phys/module_shcu_nscv.F native-shcu4/capture witness
GPUWM_WRF_EXACT=1 python tools/shallow_wrf471_replay.py \
  native-shcu4/capture/*.bin --witness witness --output replay4.json
```

The native forecast was also repeated to witness the unstable diagnostic
words in whole runs. The seeded witness identifies the full per-word
undefined set. No tendency or rain word is excluded. The GPU keeps the
incoming value for the unwritten diagnostics.

Captured native arguments, returned words, original native source,
namelists, native whole outputs for G3's no-op check, witness source and
outputs, and SHA-256 manifests live in
`~/weather/data/datasets/paper/wrf-ports/port-shcu/`. They must be retained.
The lane report carries measured timing and forecast/map evidence. The registry marks a row `supported` only after its kept native replay,
real forecast and stage timing pass. G3, GRIMS and NSCV are supported. Deng is supported as a named opt-in
with its measured cost shown below; the default remains off. Deng (`shcu_physics=5`) uses the native REAL32 driver, persistent cloud state and radiation coupling. Native WRF requires MYJ or MYNN PBL, `icloud!=3` and `icloud_bl=0`; the currently fixed MYNN EDMF identity prevents that PBL pairing, so use MYJ (`bl_pbl_physics=2`, `sf_sfclay_physics=2`). Its source-bound saturation table is generated by strict GNU REAL32 `KF_LUTAB`, with SHA-256 `dd7d5e24bb57816816f68b790b46c4c7341107edf0c2f22155df601ac5bf301a`.

## Forecast and stage timing

`tools/shallow_wrf471_timed_go.py` runs the normal `woof go` forecast.
At every shallow stage it alternates the selected scheme and an isolated
NSCV reference using the same current atmospheric inputs. Only the selected
scheme feeds the forecast. CUDA events and synchronized wall samples are
written to `WOOF_SHALLOW_TIMINGS`; the first ten steps are excluded.
The card must be free before this timing run. Set
`WOOF_KERNEL_PLAN_WORKERS=4` for parallel cold prewarming on the shared box.
The proof case uses MP21 because its prepared input contains NSSL species;
the native strict replay uses MP6. These are separate checks.

```sh
WOOF_SHALLOW_TIMINGS=stage3.json python tools/shallow_wrf471_timed_go.py \
  --wrfinput GPU_INPUT3 --outdir FORECAST3 --run-seconds 3600 \
  --no-supervise --allow-shared-gpu --products t2,refl,precip
```

Forecast maps use `rw_wrfbatch` through `woof.rustwx`.

Deng native capture and replay (private native source copy, same strict build):

```sh
python tools/deng_wrf471/capture.py NATIVE_COPY BASE_INPUT
# Build the whole native model, then run from native-shcu5 with four MPI ranks.
(cd native-shcu5 && WOOF_DENG_CAPTURE="$PWD/capture" \
  mpirun --allow-run-as-root -np 4 /absolute/path/to/NATIVE_COPY/main/wrf.exe)
GPUWM_WRF_EXACT=1 python tools/deng_wrf471/replay.py native-shcu5/capture --output deng-replay.json
```

The one-hour capture covers all columns at steps 1 and 31. It matches
6,359,760 returned words, including active cloud and precipitation, without
excluding any word. Captures, original native outputs and manifests are kept
in the permanent paper evidence directory named above.

### Deng: named opt-in, measured extra cost

`shcu_physics=5` is an explicit opt-in, never a default. In the retained
one-hour MP21/MYJ/Eta/Noah/RRTMG forecast its stage costs **3.4813x NSCV
by synchronized wall time and 34.9493x by CUDA events**, on the shared
RTX 5070 Ti. Both arms use the same atmosphere, card, commit
70120b1db46f and alternating order; 50 pairs remain after ten startup
steps. This cost is case-dependent and includes shared-card effects.
The default remains `shcu_physics=0`.

Fast Deng uses CUDA REAL32 powf/expf/logf and permits contraction. Native
libm emulation and separate rounding are confined to strict mode.
The fast PTX has no `.f64` operations; retained source hash and PTX are
in `evidence/port-shcu/deng-fast-math-audit.{json,ptx}`. Updated strict
replay still has 0/6,359,760 differing words. GNU REAL32 native profiles
show Deng's additional cloud solver, mixing/freezing, condensate loading
and time averaging. Profile command:

```sh
python tools/deng_wrf471/profile.py native-shcu5/capture native-cost-profile \
  --repeats 100 --nscv-source NATIVE_COPY/phys/module_shcu_nscv.F \
  --nscv-captures native-shcu4/capture
```

The unmodified native physics, wrappers, flags, gprof and hashes remain
in `~/weather/data/datasets/paper/wrf-ports/port-shcu/native-cost-profile/`.
The captured PBL states differ between schemes, so native CPU totals
are not a controlled speed ratio. The profiles establish extra native
work; they do not predict a fixed GPU multiplier.

The fast one-hour Deng forecast completes all 60 steps and hourly Rust
maps. All three +1h maps were inspected: cold interior, warm Florida and
Atlantic, light offshore/Bahamas reflectivity around 20–30 dBZ and small
light offshore QPF, mostly dry land, no missing tiles or clear rendering
faults. Evidence: `stage5-fast-node4.json`, `go-shcu5-fast-node4.log` and
its kept PNGs beside the lane report. This is an operation and appearance
check, not broad forecast-skill evidence.

The updated compiler-bound pack adds eight fast/strict Deng images to
the retained images, four GPU architectures each. Production loading of
all three shallow kernels with empty caches and JIT refused passes in
both modes (`deng-fast-aot-check-{fast,strict}.log`). Cold builds use four
parallel workers. The timing tool guards its CLI entry point so spawned
