# MAD-WRF cloud transport and nudging

Select `madwrf_opt=1`, `mp_physics=96` and `use_mp_re=0` for WRF's passive cloud package. MP96 transports water vapour, cloud water, ice and snow. Its native microphysics step is empty: it adds no precipitation conversion or sedimentation. `madwrf_opt=2` also transports three cloud tracers and nudges cloud water, ice and snow towards them. Both modes are explicit options; MAD defaults to off.

`madwrf_cldinit=1` enables cloud initialization. `madwrf_dt_relax` is the positive relaxation time in seconds, default 60. `madwrf_dt_nudge` is the nudging duration in minutes, default 60. Mode 2 and cloud initialization require an active package with cloud water, ice and snow. MP96 has no effective radii; its qualified cloud-radiation route uses legacy RRTMG. The importer, planner and run door enforce WRF's mode 1 requirement of MP96 and `use_mp_re=0`.

Strict GNU REAL32 WRF 4.7.1 replay has zero differences in 703,950 output words for mode 1 and 4,413,936 for mode 2, including production tracer initialization. The cloud module is unchanged from 4.6.1; this port reuses the earlier CUDA implementation and retains WRF's public-domain treatment. [Replay instructions](../../../tools/madwrf_wrf471_oracle/README.md) give the source pin, flags and commands. Native inputs and reference outputs remain under `paper/wrf-ports/port-madwrf-raoffset/madwrf_opt1/` and `madwrf_opt2/`, with manifests, hashes and sizes.

The real replay has no satellite observations: all four observation flags are zero. Historical synthetic observation cases are supplementary. No real satellite forecast skill or above-model-top observation result is claimed. Native WRF reads beyond its `dz` array when an observation reaches above the model top; the port's bounded lookup returns no level, as declared in `woof/core/madwrf.py`. That branch is outside the real replay claim.

Both modes completed fast-numerics, one-hour forecasts on a 3 km grid, 300 steps each, with hourly Rust maps inspected. The temperature fields are continuous, with a warm southwest corner and northeast and cooler west-central areas. This establishes finite fields in this case. Default-off forecasts before and after have 111,928,472 bytes of byte-identical complete history output.

On an RTX PRO 6000 Blackwell, mode 1 costs **1.0030×** MAD-off with the same MP96 water package: median final scalar transport plus the MAD hook is 0.401888 ms versus 0.400672 ms. Mode 2 costs **1.7384×**: 0.703360 ms versus 0.404608 ms, including 0.020448 ms for nudging. Mode 2 is a named opt-in (`madwrf_opt=2`), never a default. These are affected-stage costs, not whole-forecast ratios. Each complete one-hour forecast supplies 300 alternating private on/off pairs on the same source and quiet timing card; the first warm pair is excluded. Field copies, clock resets and other resets are outside the events. Host load is below 60 at both ends. [Qualification receipt](../../evidence/madwrf471/qualification.json) records raw receipt hashes and all measurements.

Mode 2's extra work also exists in native WRF: three tracer transports add a median 0.301682 seconds per native step in the retained five-step BENCH profile, compared with zero median tracer time with MAD off at the same MP96. This shared CPU profile establishes extra native work. The GPU measurements above establish the option's GPU cost. The native patch, namelists and logs are retained with the paper evidence.
