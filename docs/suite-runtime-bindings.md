# Bind an admitted suite to prepared inputs

`woof suite run FILE --bindings deployment.json` consumes the spec planner's
`gpuwm.suite.plan.v1` reservations. The same option works with rehearse and apply,
including their MCP tools. Admission, inventory, rates and forecast settings
come from FILE. The binding document cannot change them. Its `suite_sha256`
must equal the canonical resolved suite hash returned by `suite plan --json`.

```json
{
  "schema": "gpuwm.suite.bindings.v1",
  "suite_sha256": "HASH_FROM_PLAN",
  "boxes": {
    "r": {
      "launcher_prefix": ["card-lease", "box-suite-loop", "--cards", "{cards}", "--min-cards", "{cards}", "--est", "600", "--wait", "3600", "--"]
    }
  },
  "rows": {
    "forecast": {
      "base_config": "/workspace/shared-prepared/{cycle_compact}/experiment.toml",
      "source_receipt": "/workspace/shared-prepared/{cycle_compact}/suite-prepared.json",
      "source_bindings": {
        "SOURCE_REGISTRY_ID": {"selected.fetch.source": "FETCH_DOOR_SOURCE"}
      },
      "run_options": {
        "prepared_root": "/workspace/shared-prepared/{cycle_compact}/prepared",
        "wps_namelist": "/workspace/shared-prepared/{cycle_compact}/namelist.wps",
        "render_products": "none",
        "verify_visuals": false
      },
      "door_kind": "regional",
      "events": "{out}/events.jsonl",
      "receipts": ["{out}/run-manifest.json"],
      "artifact_globs": {"history": ["output/**/wrfout*"]},
      "cpu_stages": [
        {"kind": "products", "argv": ["EXISTING_PRODUCTS_ADAPTER", "{root}", "{cycle}", "{out}"]},
        {"kind": "verify", "argv": ["EXISTING_OBS_SCORECARD_ADAPTER", "{root}", "{cycle}", "{out}"], "score_files": ["{out}/scorecard.json"]}
      ]
    }
  }
}
```

Replace all capitalized example values. CPU adapters receive the state root so
they can find completed trajectory receipts in the ledger. Products depend on
every forecast member; verification depends on products. Both stages use zero
cards. Publishing is not generated by this adapter. Map adapters must call the
Rust renderer through `woof.rustwx`.

The preparing owner writes this atomic receipt only after preparation finishes:

```json
{
  "schema": "gpuwm.suite.prepared.v1",
  "suite_sha256": "HASH_FROM_PLAN",
  "row": "forecast",
  "source": "SOURCE_REGISTRY_ID",
  "lbc_source": "BOUNDARY_SOURCE_REGISTRY_ID",
  "cycle": "2026-10-03T12:00:00Z",
  "files": [{"path": "/absolute/prepared/experiment.toml", "sha256": "FILE_HASH"}]
}
```

List the base configuration and prepared input authorities with absolute paths
and SHA256 hashes. The controller checks them on the CPU before queue admission.
A derived-config row that binds no `run_options.prepared_root` is prepared
automatically: the controller adds a zero-card `ROW.prepare` stage per cycle
(`python -m woof.nwpsuite.prepare`, which runs `woof go CONFIG --prepare-only`
on the configuration derived from `base_config`, or from the row's recipe when
none is bound) and writes this receipt itself at
`STATE/prepared/ROW/CYCLE/suite-prepared.json`, with `prepared_root`,
`experiment_config` and `wps_namelist` beside the hashes. The forecast depends on
that stage and runs on the published bundle, so preparation never holds queued
forecast cards. `selected.fetch.source` defaults to the selected initial source.
If the row has a boundary-source ladder, lbc_source must belong to that ladder.
A missing receipt enters the bounded source-late ladder. Wrong identity or a
changed hash refuses the row. This receipt does not qualify the scientific
contents of the inputs. Source readiness can also be supplied as a bounded
`readiness_argv` CPU command using the existing door's 0/75/2 contract.

The adapter emits a distinct validated configuration and run-plan per member,
cycle and attempt. Prepared geometry comes from `base_config`; the original
recipe's geometry is never silently substituted. Planner config edits carry
physics and seed choices into the existing experiment loader. Random schemes
still encounter the engine's qualification refusals. Fetch cycles use the
existing `YYYY-MM-DDTHH` grammar, fetch windows round up to whole hours, and the
forecast retains the planner's exact run_seconds. Existing prepared bundles
omit run_options.cycle because the run-plan door refuses that ignored setting.

Each member has its own ledger row (`ROW`, `ROW.member-1`, etc.). Hourly
placement, deadline, source and argv variants survive. `halt ROW` and `resume
ROW` address the whole suite row, including its members and CPU stages. Shadow
DA uses an explicitly supplied `da_argv`; absent previous-cycle background
receipts record a skipped arm and retain public analysis. Hex ensemble manifests
must be supplied as distinct one-member artifacts under the planner's exact
binding names. The adapter does not fabricate that public door's manifest.

Every cycle entry retains the hash of FILE and the binding-file hash. A separate
plan_hash selects the pinned configuration. Changing bindings during resume
does not replace the old configuration; use apply to install both at the next
quiescent boundary. Recovery of a committed launch token reads its durable
intent rather than regenerating files over an active door's output.

Lagged-member products consume `{lagged_manifest}`. The controller writes that
manifest from the preceding declared number of parent cycles, checks the
completed receipt hashes, and records reuse. Missing receipts refuse the child
with `suite_lagged_receipt_missing`; they never start replacement parent runs.
The configured CPU adapter owns ensemble product assembly from those inputs.

Rate calibration, hex preparation, public one-member hex manifest production
and cross-host transport remain integration work. Remote boxes
refuse `suite_transport_unbound` because local launch tokens and PID identities
cannot safely control another host. An admitted planner result
without the needed bindings still gives a named refusal, never a partial run.
