# The Rust workspaces' test suites, as the battery invokes them.
#
# WHAT THIS IS
#   This tree carries Cargo workspaces that are not decoration: the
#   vendored Rusty Weather renderer under tools/rustwx (every product PNG
#   a run publishes comes out of rw_wrfbatch), the GRIB decoder under
#   tools/grib1_bridge (every byte of GFS and HRRR the model initialises
#   from comes through it), and the mapped decode engine under
#   tools/rw_wps (every mapped source decodes in it by default).  All
#   ship in the release.  None of them had a leg
#   on the release battery: `pytest` cannot collect a Rust test, so the
#   whole of it was invisible to every gate a cut runs, and the only
#   thing the battery ever asked of these workspaces was that the
#   renderer BINARY existed.
#
#   project ruling, 2026-08-12 ("probably we would want tests right"),
#   makes the Rust crate tests a battery leg.  This file is that leg's
#   list, and it is a CURATED ENUMERATION for the same reason
#   tools/battery/stage1_files.txt is: a gate nobody can enumerate is a
#   gate that quietly stops being run.
#
# WHY NOT `cargo test --workspace`
#   One invocation would be faster and would report ONE number.  A crate
#   that stops being a workspace member disappears from that number
#   without changing it in any way a reader can see, and the count moves
#   for legitimate reasons on every commit, so nothing can be pinned to
#   it.  Per-package entries make the membership explicit, give the
#   manifest gate something to compare the workspace against, and let
#   each package carry its own floor.
#
# FORMAT
#   One entry per line, four fixed columns then zero or more trailing
#   tokens:
#
#       SHARD  WORKSPACE  PACKAGE  MIN_TESTS  [KEY=VALUE...] [cargo args]
#
#   SHARD      `cpu`       no card, runnable in the stage-1 environment.
#                          This is the release battery's leg.
#              `gpu`       needs a card.  Nothing is on it today --
#                          neither workspace touches CUDA -- and the
#                          column exists so a crate that grows a
#                          card-dependent test has somewhere to go other
#                          than off the list.
#              `fixtures`  needs a data set the repository does not
#                          carry, fetched from a public bucket by a
#                          script in the crate.  NOT part of the default
#                          leg, listed anyway: see the rw-sat entry.
#   WORKSPACE  repository-relative directory holding Cargo.toml AND
#              .cargo/config.toml.  The config is not optional -- it is
#              the vendored source replacement that makes --offline work.
#   PACKAGE    a member package of that workspace, by name.
#   MIN_TESTS  the expected-green contract: the entry passes when cargo
#              exits 0, reports zero failures, AND runs at least this
#              many tests.  A floor rather than an equality so adding a
#              test does not turn the leg red; a floor rather than
#              nothing because "0 passed" also exits 0, and a feature
#              flag or a `#[cfg]` that stops COMPILING a test module is
#              indistinguishable from a green run without it.  The
#              numbers below are what each package reported on its first
#              green run, 2026-08-12, cargo 1.94.0 on Windows.
#   KEY=VALUE  extra environment for that entry, same idiom and same
#              reason as tools/battery/tiles_gates.txt: an invocation
#              whose real acceptance needs a variable that lives in
#              somebody's shell history is an invocation that drifts.
#   cargo args any trailing token that is not KEY=VALUE is passed to
#              cargo verbatim, after `test --locked --offline -p NAME`.
#              This is how a package splits across shards by TARGET --
#              one entry taking `--lib`, another taking `--test <name>`.
#
#   Blank lines and lines whose first non-space character is `#` are
#   ignored.  tools/battery/run_cargo_gates.py is the runner; it prints a
#   matrix and one verdict line and its exit status is the verdict.
#
# CARGO_TARGET_DIR IS MANDATORY AND MUST BE OUTSIDE THE TREE
#   The runner REFUSES to start without it and refuses one that resolves
#   inside the repository.  This is not tidiness.  A release cut checks
#   the worktree-local renderer at tools/rustwx/target/release and hashes
#   it before it believes any leg that renders; a test leg sharing that
#   directory can rebuild, replace or lock the binary the cut is
#   adjudicating, and the two answers would then depend on which leg ran
#   last.  The gate also stays accurate about the tree: a cut refuses to
#   assemble from a dirty source tree, and target/ artefacts are exactly
#   what makes one dirty on a clone whose .gitignore has moved.
#
# OFFLINE ONLY
#   Every invocation is `cargo test --locked --offline`.  Both workspaces
#   vendor their dependencies (tools/rustwx/vendor/crates-io,
#   shared by all sixteen consumer workspaces) with a .cargo/config.toml that
#   replaces the crates.io source, so a green leg proves the vendored
#   closure is complete.  Dropping --offline would let a leg pass on a
#   box with a warm registry cache and fail on the release box, which is
#   the same class of failure as a gate that lives in a shell history.
#
# AMENDMENT DISCIPLINE
#   Same as stage1_files.txt and tiles_gates.txt: an addition carries its
#   REASON inline, on the lines above it, naming what the package covers.
#   tests/test_cargo_gate_manifest.py is the gate on this file, and it
#   checks BOTH directions -- every entry names a real workspace member,
#   and every workspace member has an entry.  That second direction is
#   how a crate that lands later joins this leg: adding it to
#   tools/rustwx/Cargo.toml's members turns the manifest gate RED until
#   somebody writes its line here, so a new crate cannot arrive already
#   ungated.  MIN_TESTS for a new entry is the count its first green run
#   reported; the runner prints that number.
