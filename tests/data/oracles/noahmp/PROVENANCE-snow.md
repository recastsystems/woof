`tools/noahmp_wrf461_oracle/build_snow.py` from the unmodified WRF v4.6.1
sources at commit `d66e442fccc04111067e29274c9f9eaccc3cef28`
(Noah-MP submodule `848f54ad3d28c4303151fe5ad83724e232694422`).

They cover `phys/module_sf_noahmplsm.F` lines 6398-7230: `SNOWWATER` (6398),
`SNOWFALL` (6539), `COMBINE` (6610), `DIVIDE` (6792), `COMBO` (6920),
`COMPACT` (6974) and `SNOWH2O` (7085).

## Accessibility lift

Every routine in this span carries an explicit `private ::` accessibility
statement at `module_sf_noahmplsm.F` lines 26-84, so none is reachable from a
program that compiles the pinned source unmodified. `snow_visibility_patch.py`
lifts all 50 of them and proves the lift cannot change numerics:

- **textual**: the diff is nothing but the 7-byte token `private` becoming
  `public `, so the file length and every byte offset are preserved. Any other
  differing line, any length change, any line-count change and any
  accessibility statement left unlifted is a failure.
- **generative**: pristine and patched are compiled and compared. The `.o`
  files are **not** byte-identical, and the reason is stated rather than
  glossed: gfortran gives a `private` module procedure *local* ELF binding, so
  an intra-module call is assembled to a resolved PC-relative displacement,
  while `public` gives it *global* binding, so the same call site emits a zero
  displacement plus an `R_X86_64_PLT32` the linker resolves to the identical
  address. What is checked is therefore the set of properties that actually
  matter: identical section inventory and sizes (`.text` 260575 bytes,
  `.rodata` 6400, `.data` 28, `.bss` 17752, `.eh_frame` 2968 in both);
  byte-identical contents for every allocatable section other than `.text`;
  identical `.text` disassembly once each relocated call operand is written as
  its target symbol; every defined symbol keeping its address and size, with
  the only binding changes being exactly the 50 the patch lifted; and an
  unchanged set of undefined symbols, so the patched object gained no external
  dependency.

Three negative controls prove both checks can fail: a numeric edit (`TFRZ`
273.16 -> 273.17) is rejected by both, and a whitespace-only reindent is
rejected by the textual check.

## Option identity

Nothing in this span is option-gated (`SNOWWATER`'s callees run under every
Registry default) so there is no dead branch to assert off. The leaves
consult exactly two `noahmp_parameters` components, `SSI` and `SNOW_RET_FAC`,
and `build_snow.py` step 5 audits the pinned source text to confirm that,
because the harness supplies only those two. MPTABLE's pinned values are
`SSI = 0.03` and `SNOW_RET_FAC = 5.e-5`; three SNOWH2O cases vary them to bind
them as arguments rather than as constants. `NSNOW = 3`, `NSOIL = 4`, soil
interfaces `-0.10 / -0.40 / -1.00 / -2.00 m`.

The only WRF code in range these vectors do not admit is the glacier column's
separate `SNOWWATER` copy in `module_sf_noahmp_glacier.F`.

## `noahmp-snow.csv`

Columns `leaf,case,stage,field,index,dtype,value,bits`. 113 cases, 9,307 data
rows. `index` is the Fortran subscript, so snow layers run `-2 .. 0` and soil
layers `1 .. 4`. Reals carry both a round-tripping decimal form and the raw
IEEE binary32 bit pattern; consumers compare bit patterns, so no parsing
tolerance exists anywhere. Each case emits its **complete** entry state and
its complete exit state, so a row is reproducible from the file alone and any
argument a leaf does not touch is visibly identical across the two stages.

### Layer-count transitions

COMBINE, DIVIDE and COMBO restructure the pack, so the fixture binds layer
count changes in both directions rather than steady state:

| Transition | Bound by |
|---|---|
| `0 -> -1` | `snowfall_new_layer_{cold,warm,no_precip}`, `snowfall_limit_exact`, `snowwater_bare_to_one_layer` |
| `-1 -> -2` | `divide_single_to_two`, `divide_limit_just_above`, `snowwater_one_to_two_layers` |
| `-2 -> -3` | `divide_two_to_three_{cold,inverted}`, `divide_promote_limit_just_above` |
| `-1 -> -3` | `divide_single_to_three` |
| `-3 -> -2` | `combine_thin_ice_{mid,bottom_multi}`, `combine_thin_dz_{top,bottom,mid_up,mid_down}`, `combine_dzmin{1,2,3}_below` |
| `-3 -> -1` | `combine_double_merge_exit` (two merges, then the `ISNOW >= -1` EXIT) |
| `-2 -> -1` | `combine_ice_limit_exact`, `snowh2o_internal_combine`, `snowwater_two_to_one_layer` |
| `-1 -> 0` | `combine_last_layer_to_ponding`, `combine_oversub_*`, `snowh2o_internal_combine_to_zero`, `snowwater_one_layer_to_bare` |
| `-2 -> 0` | `combine_collapse_thin_pack` |
| `-3 -> 0` | `combine_collapse_negative_ice` |

`combine_collapse_negative_ice` is the only route to
`IF(SNEQV <= 0.0) SNOWH = 0.0`. Reaching it needs a bottom layer with negative
`SNICE` that merges *upward* into an already-visited slot, so the surviving
pack carries `ZWICE <= 0`; every other path either merges the deficit away or
exits through the `ISNOW == -1` ponding branch.

`snowwater_combine_then_divide` pins the case where COMBINE takes `ISNOW` to
`-1` and DIVIDE immediately splits the survivor back to `-2`. The composed
layer count is unchanged, which is exactly why SNOWWATER cannot be validated
by its layer count alone.

### Threshold straddles

Every comparison constant is bracketed by a pair of cases one float32 ULP
apart, so any change to the constant (down to its last bit) flips a branch:
`DZMIN(1)`, `DZMIN(2)`, `DZMIN(3)`; SNOWFALL's 0.025 m; COMBINE's 0.025 m
collapse limit and 0.1 mm ice limit; COMPACT's `VOID > 0.001`,
`SNICE > 0.1` and `SNLIQ > 0.01*DZSNSO`; DIVIDE's 0.05 m at both of its
sites and 0.2 m at both of its sites; SNOWH2O's `SNOWH <= 1e-8`,
`SNEQV <= 1e-6` and `WGDIF < 1e-6`; and SNOWWATER's `SNEQV > 5000`. The
mutation study is what established these were needed: a 0.1% perturbation of
each constant survived the looser brackets that preceded them.

### Two WRF hazards, pinned rather than assumed

`COMBINE` declares `PONDING1`/`PONDING2` `INTENT(OUT)` but assigns them on
only some paths. gfortran passes scalar dummies by reference, so an unassigned
path leaves the caller's value standing. Every COMBINE case is entered with a
`-999.0` sentinel and both the entry and the exit value are recorded, so the
observed behaviour is pinned instead of guessed; `combine_already_zero` and
`combine_thin_ice_mid` return the sentinel untouched, `combine_collapse_*`
assign `PONDING2`, and `combine_last_layer_to_ponding` assigns `PONDING1` but
not `PONDING2`.

`DIVIDE`'s `DZ`/`SWICE`/`SWLIQ`/`TSNO` slots above `ABS(ISNOW)` are
conditionally assigned locals. `build_snow.py` step 7 re-runs the entire
fixture under `-finit-real=snan -finit-integer=-2147483647` and requires
byte-identical output, so no emitted value reads uninitialised memory.

## `noahmp-snow-expf.csv`

36,002 samples of REAL(4) `EXP` over `[-45, 0]` (24,001 points) and `[-2.5, 0]`
(12,001 points). gfortran lowers REAL(4) `EXP` to `expf@plt`, so this is the
live glibc 2.39 `expf`'s own output.

`[-45, 0]` strictly contains every argument COMPACT can produce: `-C4*TD` with
`TD = MAX(0, TFRZ-STC)` gives `[-11, 0]`; `-46.0e-3*(BI-DM)` with
`BI <= DENICE` gives `[-38, 0]`; `-0.08*TD - C2*BI` gives `[-41, 0]`. The
sweep is dense enough that all 32 `__exp2f_data` table entries are selected
many times over, which `test_expf_sweep_selects_every_table_entry` asserts
rather than assumes.

This fixture exists because CUDA's `expf`, `__expf` and `exp2f` are all
different functions from glibc's, so `gpuwm/core/kernels/noahmp_snow.cu`
carries its own transcription of glibc's algorithm. Gating that transcription
on the eleven COMPACT cases alone would let a mis-folded `__constant__` table
entry hide in a leaf that never selects it.

### Mutation study

`tools/noahmp_wrf461_oracle/mutation_study_snow.py` generates 144 mutants,
one per argument each leaf consumes, plus one per `_f()` constant site, and
runs each through the CPU gate. **142 are killed.** The two survivors are
proven inert by test rather than argued in prose:

- the incoming `ZSNSO` is dead in both COMPACT (which never mentions it in its
  executable body) and SNOWWATER (which rewrites every element before anything
  reads it). `test_zsnso_incoming_value_is_dead` poisons it with NaN and
  requires bitwise-identical output.
- COMPACT's `MAX(1.0E-6, FICEOLD)` divisor cannot change an output: the
  `SNICE > 0.1` guard bounds `FICE` below, so whenever the floor is selected
  (`FICEOLD < 1e-6`) the numerator `FICEOLD - FICE` is already negative and
  `MAX(0.0, ...)` returns zero regardless of the divisor.
  `test_compact_ficeold_floor_is_unreachable` checks that over 200,000 samples
  spanning six decades of pack mass.

The first pass killed only 123 of 144. The 21 survivors were a genuine fixture
defect, the thresholds were bracketed too loosely to detect a moved constant,
and are what forced the one-ULP straddles listed above.

### Device negative controls

`test_device_negative_controls` proves the GPU gate can fail on both of its
required parts: CUDA's native `expf` must be seen to disagree with glibc's
over the same sweep, and associating the `SNEQV` accumulation as
`SNEQV + (SNICE + SNLIQ)` instead of Fortran's `(SNEQV + SNICE) + SNLIQ` must
produce a different float32. The second is not hypothetical: it is the
one-ULP error the device gate actually caught during this port.

### Running the device gate

The rented box ships CUDA 13.1 as the default toolkit but a 570-series driver,
which cannot load a CUDA 13 image, and its CUDA install has no `libnvrtc`.
Point CuPy at the 12.8 toolkit that is also present:

    export CUDA_PATH=/usr/local/cuda-12.8
    export LD_LIBRARY_PATH=/usr/local/cuda-12.8/lib64:$LD_LIBRARY_PATH

This is an environment fact about that instance, not a property of the kernel.
